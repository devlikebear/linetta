# 회차 분량 Phase 4 — 원고지 매수 간이 환산

_상위 로드맵: [`roadmap.md`](./roadmap.md)_
_작성일: 2026-11-10_
_목표: 단편·장편 작품(웹소설이 아닌 작품)의 작가가 작품 전체가 200자 원고지 몇 매쯤인지 작업 공간에서 바로 보는 수직 슬라이스_
_예상 소요: 0.5일_
_전제: Phase 1~3 병합(#347, #348, #351)_

## 배경

신춘문예와 문예지 공모전, 일부 SF 공모전은 분량을 글자 수가 아니라 원고지 매수로 적는다. 예: "단편소설 원고지 70~80매", "중편 200~300매".
지금 리네타는 작품 전체 글자 수만 보인다. 작가는 글자 수를 200으로 나눠 어림하는데, 이 값은 실제 매수보다 꽤 적다.

원고지는 200칸(20칸 × 10줄)이다. 매수가 글자 수 ÷ 200보다 많은 이유는 두 가지다.

- 문단은 첫 칸을 비우고 시작한다.
- 문단이 끝난 줄의 남은 칸은 비워 둔다.

대화가 많은 소설은 짧은 문단이 많아서 차이가 더 커진다. 예를 들어 15자짜리 대사 문단은 한 줄을 다 쓴다.

## 결정

- **간이 환산이고, 화면에 그렇게 적는다.** 문단마다 "첫 칸 들여쓰기 1칸 + 글자 수"를 20칸 줄로 올림하고, 줄 수를 10으로 나눠 올림한다.
  정식 원고지 규칙은 따지지 않는다. 문장부호의 칸 차지, 줄 첫 칸 문장부호, 대화문 들여쓰기, 숫자·영문 두 자 한 칸 같은 것들이다.
  화면에는 "약 N매"로 적고, 마우스를 올리면 간이 환산이라고 설명한다.
- **공백은 작품의 글자 수 기준과 상관없이 한 칸이다.** 원고지에서 띄어쓰기는 칸을 차지한다. 그래서 "공백 제외"로 세는 작품도
  매수는 공백 포함으로 계산한다.
- **빈 문단은 세지 않는다.** 장면 전환용 빈 줄과 구분선은 작가마다 쓰는 방식이 달라서 넣으면 매수가 흔들린다.
- **줄바꿈(Shift+Enter)은 새 줄로 친다.** 새 줄은 들여쓰지 않는다. 시나 편지글처럼 문단 안에서 줄을 바꾼 글이 한 줄로 이어 붙지 않게 한다.
- **글자를 세는 범위는 글자 수와 같다.** `charcount.Doc`처럼 텍스트 노드만 센다. 글자 수와 매수가 서로 다른 본문을 보지 않게 한다.
- **씬은 이어서 쓴 것으로 본다.** 작품 전체의 줄 수를 더한 뒤 매수를 올림한다. 씬마다 새 장으로 넘기면 매수가 씬 수만큼 부풀기 때문이다.
- **계산은 엔진이 한다.** 저장할 때 미리 계산해 두지 않고, 요청할 때 작품의 본문을 읽어 센다.
  - 노드 목록이 이미 본문을 함께 읽는다(`node.Repo.ListByProject`).
  - 단편·장편 작품 하나의 본문은 수십만 자 이내라서 매번 읽어도 빠르다.
  - 저장 경로가 여러 곳이라(편집, 가져오기, 복원, 에이전트 쓰기) 칼럼을 두면 갱신을 빠뜨리기 쉽다.
- **웹소설 작품에는 보이지 않는다.** 웹소설 요강은 글자 수로 적는다. 매수까지 보이면 작가가 어느 숫자를 봐야 할지 헷갈린다.

## Goal

- 웹소설이 아닌 작품의 오른쪽 패널, "작품 전체 N" 아래에 `200자 원고지 약 104매`가 보인다.
- 씬을 저장하면 매수도 따라 바뀐다.
- 마우스를 올리면 간이 환산 규칙이 보인다.

## Non-goals

- 정식 원고지 규칙(문장부호, 대화문 들여쓰기, 숫자·영문)
- 제출 기준을 매수로 정하는 기능. Phase 3의 작품 분량 기준은 글자 수 그대로 둔다. 매수 기준이 필요하다는 요청이 있으면 따로 계획한다
- 씬·장 단위 매수
- 원고지 서식으로 내보내기(HWP·DOCX 원고지 양식)
- 에이전트 브리프와 MCP 도구에 매수 싣기. 도구 스키마 예산이 빠듯하다(29,489 / 29,500B)

## Tasks

- [ ] **4.1 환산 함수 (`charcount`)**
  - `ManuscriptLines(rawDoc []byte) int`: Tiptap 문서에서 `paragraph`와 `heading`을 문단으로 본다
    - 문단의 첫 줄은 들여쓰기 1칸 + 글자 수. `hardBreak` 뒤는 들여쓰기 없이 새 줄
    - 줄마다 칸 수를 20으로 나눠 올림. 글자가 없는 줄은 0
    - 공백도 한 칸. 텍스트 노드만 센다(`Doc`와 같다)
    - 잘못된 JSON이나 빈 입력은 0
  - `ManuscriptPages(lines int) int`: 10줄로 나눠 올림
  - 상수 `ManuscriptColumns = 20`, `ManuscriptRows = 10`
  - 테스트: 19자 문단 → 1줄, 20자 문단 → 2줄, 빈 문단 → 0, 공백 포함, `hardBreak`, 제목, 목록·인용 안의 문단, 매수 올림, 잘못된 입력

- [ ] **4.2 RPC**
  - `projects.manuscript_pages { id }` → `{ lines, pages }`. 작품의 모든 씬(leaf) 본문 줄 수를 더한다
  - 작품이 없으면 기존 not found, id가 없으면 invalid params
  - `engineapp`에 등록하고 RPC 왕복 테스트를 하나 둔다
  - Tauri 렌더러 허용 목록에 넣는다(정렬 유지)

- [ ] **4.3 작업 공간 표시**

    - 0매(빈 작품)이거나 읽기에 실패하면 아무것도 그리지 않는다

  - 세 언어 문구(`workspace.manuscriptPages`, `workspace.manuscriptPagesHint`)
  - 테스트: 매수 표시, 0매면 없음, 실패하면 없음, 갱신 키가 바뀌면 다시 읽음. `ContextPanel`에서 웹소설 작품에는 없음
