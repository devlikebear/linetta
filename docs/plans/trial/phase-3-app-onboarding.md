# 체험 공급자 Phase 3 — 앱 온보딩과 문서

_상위 로드맵: [`roadmap.md`](./roadmap.md)_
_작성일: 2026-11-11_
_목표: LLM을 연결하지 않은 작가가 에이전트 패널에서 "키 없이 체험하기" 한 번으로 웍스 연결, 동의, 체험 시작까지 가고, 남은 한도를 보며 쓰다가, 다 쓰면 자기 키로 넘어가는 수직 슬라이스_
_예상 소요: 2일_
_전제: Phase 2 병합, Phase 1 운영 배포와 `enabled: true`_

## Goal

- 공급자가 준비되지 않은 에이전트 패널에 "키 없이 체험하기"가 먼저 보이고, 그 아래에 "내 키 연결"이 있다.
- "키 없이 체험하기"는 순서대로 진행한다.
  1. 웍스에 연결되어 있지 않으면 기존 기기 연결 흐름(브라우저에서 로그인, 앱이 기다림)
  2. 체험 동의 문장(원고가 리네타웍스를 거쳐 Upstage로 간다, 리네타웍스는 내용을 저장하지 않는다)
  3. `linetta-trial`을 활성 공급자로
- 설정의 공급자 목록 맨 위에 "리네타 체험"이 있다. 키 입력 칸 대신 연결 상태, 남은 토큰, 동의 체크가 있다.
- 체험으로 도는 동안 에이전트 패널 머리에 남은 한도가 작게 보인다(예: `체험 · 2.1M 토큰 남음`). 한 턴이 끝날 때마다 새로 읽는다.
- 한도를 다 쓰면 그 턴의 오류 자리에 "체험 한도를 다 썼어요"와 "내 키 연결" 버튼이 보인다. 멈춘 경우에는 "지금은 체험을 받을 수 없어요"가 보인다.
- 체험이 아닌 공급자를 쓰는 작가에게는 아무것도 달라 보이지 않는다(목록 맨 위에 한 줄이 늘어날 뿐).

## Non-goals

- 체험 뒤 결제나 구독
- 체험 전용 튜토리얼 작품. 작가는 자기 작품이나 빈 작품에서 시작한다
- 웍스 연결 화면 다시 만들기

## Touch points

- `apps/desktop/src/lib/providers.ts`: `PROVIDER_ORDER` 맨 앞, `takesApiKey`가 false, `isProviderReady`는 그대로
- `apps/desktop/src/lib/types.ts`: `TrialStatus`
- `apps/desktop/src/hooks/useTrialStatus.ts`(새): `trial.status`를 부르고, `agent.done`, `agent.error`, 연결 변경 때 다시 읽음
- `apps/desktop/src/components/settings/ProviderSection.tsx`: 체험 행(연결 상태, 남은 토큰, 동의, "웍스 연결" 버튼은 `PublishSection`의 연결 흐름 재사용)
- `apps/desktop/src/components/settings/PublishSection.tsx`: 연결 흐름을 다른 곳에서 부를 수 있게 훅이나 함수로 꺼냄(동작은 그대로)
- `apps/desktop/src/components/agent/AgentPanel.tsx`, `ProviderPicker.tsx`: 빈 상태 카드, 남은 한도 표시, 소진·멈춤 오류
- `apps/desktop/src/lib/rpcMessage.ts`: 새 이유 두 개의 문구
- `apps/desktop/src/lib/i18n.tsx`: ko, en, ja
- `docs/privacy-policy.md`, `apps/site/src/lib/content.ts`(사이트 개인정보 문구), `README.md`, `CHANGELOG.md`

## Tasks

- [ ] **3.1 공급자 목록의 체험 행**
  - 상태별 표시
    - 연결 없음: "리네타웍스 계정으로 이 기기를 연결하면 키 없이 써 볼 수 있어요" + 연결 버튼
    - 연결됨, 동의 전: 동의 문장과 체크
    - 사용 가능: `2,134,000 / 3,000,000 토큰 남음`
    - 소진: "체험 한도를 다 썼어요. 아래에서 내 키를 연결하세요"
    - 멈춤 또는 서버에 닿지 않음: "지금은 체험을 받을 수 없어요"
  - 체험 행에는 모델 선택과 "연결 확인"(providers.test)이 없다. 서버가 모델을 정하고, 확인 요청도 한도를 쓰기 때문이다
  - 테스트: 상태 다섯 가지 렌더, 키 입력 칸 없음, 동의 체크가 `settings.set`의 `consented_at`으로 감

- [ ] **3.2 에이전트 패널 빈 상태**
  - 준비된 공급자가 하나도 없으면(`isProviderReady`가 모두 거짓) 지금의 "설정에서 공급자 연결" 안내 대신 카드 두 개
    - "키 없이 체험하기"(주): 위 Goal의 세 단계를 이어서 진행. 중간에 취소하면 아무것도 바뀌지 않음
    - "내 키 연결": 설정의 공급자 화면
  - 체험이 소진된 계정이면 첫 카드는 "체험을 다 썼어요"로 바뀌고 비활성
  - 테스트: 세 단계 진행 순서, 이미 연결된 기기는 1단계를 건너뜀, 취소 시 활성 공급자 그대로

- [ ] **3.3 쓰는 동안**
  - 체험으로 도는 턴은 패널 머리의 공급자 표시 옆에 남은 토큰(백만 단위, 소수 한 자리). 50만 아래면 경고색
  - `provider_trial_exhausted`: 오류 말풍선에 "체험 한도를 다 썼어요. 지금까지 쓴 원고와 대화는 그대로 있어요" + "내 키 연결"
  - `provider_trial_paused`: "지금은 체험을 받을 수 없어요. 잠시 뒤 다시 하거나 내 키를 연결하세요"
  - 체험 공급자에서 `provider_auth_failed`: "리네타웍스 연결이 끊겼어요" + 다시 연결
  - 테스트: 세 오류의 문구와 버튼, 턴이 끝난 뒤 남은 토큰을 다시 읽음

- [ ] **3.4 동의와 문서**
  - 체험 동의 문장(ko 기준): "체험을 쓰면 에이전트에게 보내는 원고와 대화가 리네타웍스를 거쳐 Upstage(Solar)로 전송됩니다. 리네타웍스는 내용을 저장하지 않고 사용한 토큰 수만 기록합니다."
  - `docs/privacy-policy.md`와 사이트 개인정보 문구에 같은 내용(수탁자, 목적, 저장하지 않음, 토큰 수 기록과 보관 기간)
  - `README.md`의 에이전트 연결 절에 체험을 첫 번째 방법으로, `CHANGELOG.md`
  - App Store Connect의 개인정보 라벨(사용자 콘텐츠를 제3자에게 보냄) 변경이 필요한지 확인해 릴리스 메모에 남긴다. 이 항목은 운영자 작업이다

## 확인

- `pnpm test`(desktop), `pnpm typecheck`
- 실제 앱으로 끝까지: 새 라이브러리(`LINETTA_HOME` 스크래치)에서 공급자 없이 시작 → 체험하기 → 웍스 연결 → 동의 → 짧은 질문 한 턴 → 남은 토큰 줄어듦.
  개발 서버에서 그 계정의 `used_tokens`를 `granted_tokens`로 맞춘 뒤 한 턴 더 → 소진 안내와 "내 키 연결"
- 체험이 아닌 공급자로 한 턴: 패널 모습과 도구 수(49)가 전과 같음
