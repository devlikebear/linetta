# 체험 공급자 — 로드맵

_작성일: 2026-11-11_
_상태: 계획. 2026-11-11 사용자 결정 반영(상위 모델 Solar Mini 4, 웍스 계정과 기기 연결로 식별, 계정당 1회 300만 토큰)_
_관련: [`tool-profile.md`](./tool-profile.md)(체험 도구 20개, #359 계획·#360 구현), linetta-artworks `docs/api.md`(기기 연결과 게시 API)_

## Overview

지금 리네타의 에이전트는 작가가 LLM을 직접 연결해야 쓸 수 있다. 공급자를 고르고, API 키를 받거나 로그인하고, 원고 전송에 동의해야 한다.
에이전트가 무엇을 해 주는지 보기도 전에 이 단계에서 그만두는 작가가 많다.

체험 공급자는 리네타웍스가 운영자의 키로 LLM을 대신 불러 주는 공급자다. 작가는 웍스 계정으로 이 기기를 연결하기만 하면(게시에 쓰는 그 연결)
키 없이 에이전트를 써 볼 수 있다. 정해진 토큰을 다 쓰면 자기 키를 연결하도록 안내한다.

## 가치 제안

> LLM 계정이 없는 작가도 리네타를 설치하고 웍스에 로그인하면 바로 에이전트에게 회차를 맡기고 고쳐 보게 할 수 있다.
> 체험이 끝나면 같은 작업을 자기 키로 이어 간다.

## 결정 사항

- **상위 모델은 Upstage Solar Mini 4 (2026-11-11 사용자).** $0.10 / $0.40 per 1M(캐시 입력 $0.01), 도구 호출, 512K 맥락,
  한국어 강조, API 입력을 학습에 쓰지 않는다고 밝힌다. 프록시는 OpenAI 호환 형식만 다루므로, 나중에 운영 설정으로 다른 공급자로 바꿀 수 있게 둔다.
- **식별은 웍스 계정과 기기 연결 (2026-11-11 사용자).** 게시에 쓰는 기기 연결(`lwk_` 토큰, `/api/artworks/pair/*`)을 그대로 쓴다.
  연결은 게시 권한(`can_publish`)이 없어도 된다. 익명 체험은 하지 않는다. 재설치로 한도를 다시 받는 길을 막기 위해서다.
- **한도는 계정당 1회 300만 토큰 (2026-11-11 사용자).** 실측한 체험 1인분(질문 10, 퇴고 10, 새 회차 3)은 체험 도구 기준 약 150만 토큰이라,
  300만 토큰이면 두 배쯤 쓸 수 있다. 입력과 출력을 같은 토큰으로 센다. 다 쓰면 끝이다. 운영자는 계정별로 더 줄 수 있다.
  한 계정이 300만 토큰을 다 써도 Solar Mini 4로 약 $0.31(캐시 없이)이다.
- **비용 상한은 서버가 지킨다.** 계정 한도와 별개로 월 지출 상한(달러)을 운영 설정에 둔다. 넘으면 체험 전체를 멈추고 앱에 "지금은 체험을 받을 수 없음"을 알린다.
- **체험 턴은 도구 20개로 돈다.** [`tool-profile.md`](./tool-profile.md)의 프로필을 체험 공급자가 켠다. 실측 절감은 40~49%다.
- **원고는 지나가기만 한다.** 프록시는 요청과 응답 본문을 저장하지도, 로그에 남기지도 않는다. 남기는 것은 계정, 기기, 토큰 수, 시각, 결과 코드뿐이다.
- **프록시는 Node 서비스로 따로 둔다.** 에이전트는 스트리밍으로 받는데, PocketBase JS 훅의 `$http.send`는 응답을 다 받은 뒤에야 돌려준다.
  그래서 SSE를 그대로 흘려 주는 작은 Node 서비스(`artworks-trial`)를 두고, 인증과 한도는 PocketBase 훅에 맡긴다. 수위 검사 워커가 서비스 계정으로 PocketBase를 부르는 방식을 그대로 따른다.

## Phases

| Phase | 저장소 | 내용 | 산출물 |
|---|---|---|---|
| [1](./phase-1-works-proxy.md) | linetta-artworks | 체험 프록시와 한도 원장 | `/api/trial/v1/chat/completions`, `trial_usage`, 운영 설정, 배포 |
| [2](./phase-2-engine-provider.md) | linetta | 엔진 체험 공급자 | `linetta-trial` 공급자, `trial.status`, 체험 도구 켜기, 한도 소진 오류 |
| [3](./phase-3-app-onboarding.md) | linetta | 앱 온보딩과 문서 | "키 없이 체험하기", 남은 한도 표시, 동의 문구, 개인정보 문서 |
| 4 | 둘 다 | 실측 Checkpoint | 실제 Solar로 세 시나리오를 돌려 1인분 비용과 품질 확인, 한도 조정 |

Phase 1을 먼저 배포한다. Phase 2는 Phase 1의 개발 서버에 붙여 테스트하고, Phase 3까지 끝나야 사용자에게 보인다.

## Phase 4 Checkpoint (실측)

- 체험 계정 하나로 질문, 선택 문단 퇴고, 새 회차 쓰기를 각각 세 번 이상 돌린다
- 확인할 것
  - Solar Mini 4가 리네타의 도구 호출 루프를 끝까지 도는지(빈 응답, 도구 인자 오류, 같은 도구 반복)
  - 한국어 소설 문장 품질이 체험으로 보여 줄 만한지. 사용자 판정
  - 실제 청구액과 `trial_usage`에 적힌 토큰이 맞는지, 캐시 입력이 실제로 싸게 잡히는지
  - 1인분 비용이 실측 추정(약 $0.16, 캐시 적용 시 더 낮음)과 얼마나 다른지
- 결과에 따라 300만 토큰 한도와 월 상한을 조정한다. 품질이 모자라면 상위 모델을 바꾸는 결정은 사용자에게 올린다

## 이후

- 남은 큰 도구 설명 두 개(`apply_story_ops`, `report_continuity`)를 체험용으로 줄일지
