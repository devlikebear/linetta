# 동기화 Phase 3 — 측정 (T3.1)

_측정일: 2026-11-01_
_재현: `cd engine && LINETTA_MEASURE=1 CGO_ENABLED=0 go test ./internal/vault -run TestMeasureLargeWork -v`_

## 조건

작가의 서재(6편 약 14 MB)보다 훨씬 큰 작품 하나를 임시 서재에 만들었다. 씬 200개, 씬마다 4,000자, 씬마다 스냅샷 10개, 삽화 60장(장당 320 KB, 압축되지 않음)이다.
본문은 무작위 음절이다. 반복 문장은 실제 글보다 훨씬 잘 압축되어 전송량을 숨긴다(같은 조건에서 121 MB가 37 KB로 줄었다).

## 결과

| 항목 | 값 |
|---|---|
| 평문 크기 | 44 MB (삽화 18, 이력 23, 나머지 2) |
| `export` 한 번 | 약 80 ms |
| 첫 올리기 전송량 | 21.9 MB, 조각 70개 |
| 첫 올리기 시간 (가짜 사이트) | 207 ms |
| 씬 하나를 고친 올리기 전송량 | 2.4 MB |
| 씬 하나를 고친 올리기 시간 (가짜 사이트) | 166 ms |

## 결정

- **`data_version` 건너뛰기는 하지 않는다.** 이 큰 작품도 80 ms라 5분 주기에 부담이 없고, 작가의 서재 전체는 그보다 작다. `PRAGMA data_version`은 다른 연결의 커밋만 보는데 엔진은 연결이 하나(`store.Store`)라 쓸 수도 없다. 스킬과 메모리 파일도 볼 수 없다.
- **`node_snapshots` 파트는 나누지 않는다.** 파트는 4 MB 단위로 잘리므로 행이 끼어들면 뒤쪽 조각이 모두 바뀌어, 씬 하나에 2.4 MB가 나간다. 이 작품으로 하루 20번 올려도 50 MB이고 쿼터는 복원 지점 몇 개만큼만 쓴다. 작가의 실제 이력은 전체 3 MB라 훨씬 작다. 파트를 나누면 번들 형식이 바뀌므로 며칠 쓴 뒤 다시 판단한다.
