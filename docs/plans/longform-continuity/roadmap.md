_상태: Phase 1~5 구현 완료. 실제 Claude Code 호출과 실제 원고 평가는 작가의 데이터 공유 동의를 기다린다. Phase 6~7 구현 완료(2026-11-10). Phase 8은 계획 단계다(2026-11-10 추가)_

## Overview

연재가 길어지면 에이전트가 앞에서 정한 사실을 놓치고, 설정이 바뀌면 앞 회차가 어긋난다. 16화까지 쓴 작품에서 이 문제가 반복됐다. 먼 회차의 모순은 작가가 직접 "1화가 이상하다"고 요청한 뒤에야 나왔다.

원인은 모델 성능 하나가 아니다. 브리프가 도구 결과 상한을 넘어 잘리고, 확정 사실이 복선에 밀려 빠지고, 전체 목록 도구도 잘리고, 설정 변경이 앞 회차로 전파되는 경로가 없다. 기록은 회차 수에 비례해 늘어나는데 읽을 수 있는 양은 고정돼 있다.

이 계획은 리네타를 **기록을 쌓는 도구에서 현재 상태를 유지하는 도구**로 옮긴다. 먼저 지금 무너진 용량을 복구하고, 작가가 작품 규칙을 고정하게 하고, 사실에 유효 회차를 붙이고, 아크마다 기록을 닫는다. 1,000화를 보장한다고 말하지 않는다. 각 단계에서 어디까지 지원되는지 측정해서 밝힌다.

## 가치 제안

> 작가는 몇 화를 쓰든 에이전트가 작품 규칙과 현재 상태를 아는 상태에서 일하고, 설정을 바꾸면 고칠 회차를 근거와 함께 받는다. 원고는 작가가 승인한 만큼만 바뀐다.

## 근거 (2026-11-02 실측)

설치된 앱의 DB 복사본에서 쟀다. 작품 하나, 16화, 약 6만 2천 자, 사흘치 기록이다. 브리프는 실제 엔진 코드로 재현했다. 문서에는 집계 수치만 남기고 작품 내용은 쓰지 않는다.

- **브리프 초과:** 쓴 회차 브리프가 29,800~31,600자다. `maxToolResultChars`는 24,000자다. JSON 이스케이프를 넣어 계산하면 6,200~8,000자가 잘리고 세계관 뒷부분, 플롯, 관계, 자료집이 빠진다. 안 쓴 회차도 24,078자다.
- **정해진 사실 소실:** 샘플 5개 회차 모두 원장의 `Settled`가 0건이고 32~36건이 생략된다. 예산 3,000자를 복선이 먼저 쓴다. 표본 사실 13개 중 10개의 키워드는 세계관 카드로 들어왔고, 표기 규칙 3개는 어디에도 없었다.
- **목록 도구 초과:** 원장 전체가 약 45,500자, 세계관 전체가 약 30,000자다. 원장은 오래된 순이라 최근 결정이 잘린다. `linetta_get_outline`은 약 120행에서 잘린다.
- **자리 배분:** 자료집이 매번 4,521자, 쓴 회차의 본문 중복이 약 4,200자, 세계관 카드가 8,800~10,200자를 쓴다.
- **전파 부재:** 결정을 기록한 25턴 중 17턴에 원고 검색이 없었다. 규칙은 매 턴 프롬프트에 보였다. 프롬프트 규칙만으로는 강제되지 않는다.
- **먼 모순:** 8화 이상 떨어진 모순 5건은 모두 작가가 요청한 1화 검수에서 나왔다.
- **언급 빈틈:** 1화의 언급이 0건이다. 다른 회차는 34~60건이다. 언급 기준으로 쌍을 고르면 먼 모순 3쌍이 120쌍 중 64~114위로 밀린다.
- **표본 대조:** 기록된 모순 쌍 9개로 소급 시험했다. 54회 기준 순수 무작위는 4.1쌍, 앵커·직전 2화·무작위 1개의 층화 표본은 8.2쌍을 덮었다. 직전 2화만 보면 먼 모순은 0쌍이다.
- **증가율:** 화당 원장 3.6건, 세계관 요소 3.5개, 열린 원장 1,042자, 대화 12,980자, 작가 메시지 8.6건이다. 선형이면 1,000화에서 원장 3,600건이 된다.
- **엔진 속도:** 합성 1,000화 작품의 브리프 생성이 0.24초다. 병목은 속도가 아니라 기억 구조다.

재현 방법과 실패 사례는 저장소에 넣지 않고 로컬에 둔다. 과거 시점의 잘림은 로그에 남지 않아 지금 데이터로 재현한 값이다.

## 결정 사항

- **저장소를 새로 만들지 않고 원장을 확장한다.** `story_ledger`에 고정 여부, 속성, 유효 회차, 대체 관계를 더한다. 화면, vault 번들, 복원이 원장을 이미 다룬다. `copyRows`는 `SELECT *`라 새 열을 그대로 옮긴다.
- **작품 규칙은 별도 문서가 아니라 고정한 원장 항목이다.** 고정은 앱 RPC로만 한다. 에이전트는 고정 항목을 바꾸거나 지우지 못한다.
- **현재 상태는 모델이 쓴 문서가 아니라 조회 결과다.** 회차 시점의 유효한 원장 행에서 계산한다. "자동 요약은 넣지 않는다"는 memory-search의 결정을 유지하고, 상태판이 낡을 일도 없앤다.
- **엔진은 LLM을 부르지 않는다.** 정산과 영향 검사는 내장 에이전트 패스로 만든다. 패스는 `runPass`로 돌린다. Claude Code는 도구 호출을 돌려주지 않으므로 `boundedPass`만으로는 돌지 않는다. 충돌 감지처럼 코드로 되는 일은 엔진이 결정적으로 한다.
- **대조는 같은 주어·속성의 사실끼리 한다.** 전체 원고를 다시 읽지 않는다. [FlawedFictions](https://arxiv.org/abs/2504.11900)는 LLM의 구멍 탐지가 긴 이야기에서 크게 떨어진다고 보고한다.
- **표본 대조는 대화 기록 없이 돌리되 순수 무작위로 하지 않는다.** 특정 쌍을 3화 묶음 무작위로 90% 확률로 덮으려면 100화에서 약 3,800회, 1,000화에서 약 38만 회가 든다. 층화 표본은 회차당 호출이 일정해 회차 수에 비례한다. [모든 쌍 테스트](https://en.wikipedia.org/wiki/All-pairs_testing)와 레코드 연결의 블로킹을 참고했다.
- **대화 한도 기본값은 그대로 둔다.** 100,000자는 memory-search Phase 3의 실측 결과다. 대화 경계는 작가가 직접 긋는 선택 기능이고, 지우지 않는다.
- **원고는 자동으로 고치지 않는다.** 패스는 후보만 기록한다.
- **실제 원고와 실패 사례는 저장소에 넣지 않는다.** 회귀 테스트는 실제 크기를 흉내 낸 합성 데이터로 만들고, 실제 작품 평가는 로컬에서만 한다.

## 기존 작업과의 관계

중복과 롤백을 막기 위해 페이즈 시작 전에 이 표를 다시 확인한다.

| 기존 작업 | 이 계획의 처리 |
|---|---|
| #269 브리프 예산, 문체 우선 | 유지한다. 합성 데이터라 초과를 못 잡은 상한 테스트만 실제 크기로 강화한다. |
| #272 원장, 회수 우선 | 유지한다. `TestBriefNeverReadsAheadAndPutsDueFirst`를 건드리지 않는다. 순서는 그대로 두고 예산을 나눈다. |
| #272 독립 검수 기본 꺼짐 | 유지한다. 이 패스는 Claude Code에서 한 번도 돌지 않았다. Phase 3에서 `runPass`로 고쳤다. 실호출 측정은 작가 동의가 필요해 남아 있고, 기본값은 측정 뒤 작가가 정한다. |
| memory-search 대화 검색·보관·한도 | 유지한다. 경계는 기존 창(`historyStarts`)과 검색 도구 위에 얹는다. 모델 인계문은 계속 만들지 않는다. |
| `contextualedit` 이름 변경 검사 | 유지한다. 결정적 표현 검사이고 의미 대조가 아니므로 영향 검사와 겹치지 않는다. |
| 씬 의도, 작품 초점 | 0건이지만 작가 소유 기능이다. 집필 계약을 새로 만들지 않고 건드리지 않는다. |
| #281 연속성 일괄 정리 | 유지한다. `resolved`를 코드가 검증하게 바꾸는 일은 Out of Scope다. |
| #137, #141 | 새 이슈를 만들지 않는다. Phase 4의 영향 검사와 Phase 5의 평가를 여기에 붙인다. |

## 완료 조건 (전체)

- [ ] 실제 크기의 작품에서 브리프가 도구 결과 상한 안에 온전히 들어온다.
- [ ] 정해진 사실과 작가가 고정한 작품 규칙이 어느 회차 브리프에든 들어온다.
- [ ] 목록 도구가 잘리지 않고 페이지로 끝까지 읽힌다.
- [ ] 작가가 대화를 새로 시작해도 앞 대화가 지워지지 않고 앱을 재시작해도 경계가 유지된다.
- [ ] 회차 시점의 현재 상태가 브리프에 나오고, 어긋나는 사실을 쓰면 충돌로 알려 준다.
- [ ] 설정을 바꾸면 영향받는 회차가 근거와 함께 후보로 기록된다.
- [ ] 대화 기록 없이 회차 두세 개를 맞대어 먼 회차의 모순을 찾는 표본 대조가 동작한다.
- [ ] 아크를 닫으면 브리프의 열린 복선이 현재 아크와 상위 범위로 줄어든다.
- [ ] 합성 1,000화에서 상한 불변식이 통과하고, 일관성 평가 결과가 #141에 기록된다.

## 기술 스택 / 환경

- **엔진**: Go, `modernc.org/sqlite`, FTS5 trigram
- **앱**: Tauri 2, React 18, TypeScript (`apps/desktop`)
- **도구 표면**: `engine/internal/mcphost`. 내장 에이전트는 같은 도구를 인메모리로 쓴다.
- **로컬 검증**: `engine/`에서 `CGO_ENABLED=0 go test ./...`. cgo 빌드는 macOS 키체인을 건드려 멈출 수 있다. `-race`는 CI에 맡긴다.
- **모바일**: 마이그레이션은 모바일에도 적용된다. `make test-mobile-engine`으로 확인한다.
- **의존성 규칙**: `storycontext`는 LLM 코드를 가져오지 않는다. `scripts/validate-story-core-deps.sh`로 확인한다.
- **문구**: 화면 문구는 `apps/desktop/src/lib/i18n.tsx`의 세 언어를 모두 쓴다. 새 RPC는 `apps/desktop/src-tauri/src/lib.rs` 허용 목록에 더한다.

## Out of Scope

- **원고 전면 재생성**: 작가의 교정이 사라지고 생성이 구멍을 늘린다. 재작성은 작가가 지정한 회차에서만 지금처럼 한다.
- **그래프 DB, 벡터 검색**: SQLite 사실 조회로 시작한다. 벡터는 Phase 5에서 표현 변형으로 놓치는 사례가 실측될 때만 다시 본다.
- **대화 한도 기본값 변경, 턴 중간 컨텍스트 교체, 모델 인계문**: memory-search에서 정한 범위를 따른다.
- **갈래 예측 삭제, 제안함 도구 통합, 삽화·게시 도구 분리**: 컨텍스트 효과가 작거나 작가 결정이 필요하다. 이 계획에 묶지 않고 따로 판단한다.
- **`resolved` 자동 검증**: 해결 표시의 인용 대조는 Phase 5 결과를 보고 판단한다.
- **게시 회차 수정 차단**: 경고만 한다.
- **자료집 사실 검증 자동화**: 범위 밖이다.

## 페이즈 구성

각 페이즈는 끝나면 동작하는 무언가가 나오는 수직 슬라이스다.

### Phase 1: 브리프 용량 — 지금 잘리는 것을 복구한다

- **목표**: 어떤 회차든 브리프가 상한 안에 들어오고, 정해진 사실이 보이고, 목록이 끝까지 읽힌다.
- **포함 기능**: 실제 크기 회귀 테스트, 브리프 재배분, 원장 예산 분리, 목록 페이지
- **예상 소요**: 1.5일
- **작업지시서**: [`phase-1-brief-capacity.md`](./phase-1-brief-capacity.md)
- **Checkpoint 요약**: 실제 DB 복사본의 모든 회차 브리프가 상한 안에 들고 `Settled`가 비지 않는다.

### Phase 2: 작가 경계 — 규칙을 고정하고 대화를 새로 시작한다

- **목표**: 작가가 고른 작품 규칙이 항상 브리프에 들어가고, 작가가 대화 경계를 그을 수 있다.
- **포함 기능**: 원장 고정, 대화 경계, 시작 칩
- **예상 소요**: 1일
- **작업지시서**: [`phase-2-writer-boundaries.md`](./phase-2-writer-boundaries.md)
- **Checkpoint 요약**: 에이전트가 고정 항목을 못 바꾸고, 경계가 재시작 뒤에도 유지되며 검색은 그대로 된다.

### Phase 3: 시점 사실과 정산 — 회차 시점의 현재 상태를 안다

- **목표**: 원장 사실에 유효 회차가 붙고, 현재 상태가 브리프에 나오고, 충돌이 쓰는 순간 드러난다.
- **포함 기능**: 독립 검수 실호출 스파이크, 원장 확장, 현재 상태, 충돌 감지, 정산 패스
- **예상 소요**: 3일
- **작업지시서**: [`phase-3-temporal-facts.md`](./phase-3-temporal-facts.md)
- **Checkpoint 요약**: 회차를 앞뒤로 옮겨 가며 현재 상태가 달라지고, 어긋나는 사실이 `conflicts`로 돌아온다.

### Phase 4: 아크 결산과 영향 검사 — 기록을 닫고 변경을 전파한다

- **목표**: 권·아크로 작품을 나누고, 아크를 닫으면 기록이 줄고, 설정 변경이 앞 회차 후보로 이어진다.
- **포함 기능**: 권·아크 계층, 복선 범위, 영향 검사, 표본 대조, 결산·재구축 칩, 작품 복제, 게시 경고
- **예상 소요**: 3.5일
- **작업지시서**: [`phase-4-arc-closing.md`](./phase-4-arc-closing.md)
- **Checkpoint 요약**: 합성 작품에서 설정을 옮기면 영향 회차를 찾고, 아크를 닫으면 브리프의 열린 복선이 줄어든다.

### Phase 5: 규모 평가 — 어디까지 되는지 밝힌다

- **목표**: 합성 1,000화와 실제 작품으로 지원 범위를 측정해 문서로 낸다.
- **포함 기능**: 상한 불변식, 평가 하네스, 지원 범위 문서
- **예상 소요**: 1.5일 (실사용 관찰 별도)
- **작업지시서**: [`phase-5-scale-eval.md`](./phase-5-scale-eval.md)
- **Checkpoint 요약**: #141에 재현 가능한 수치가 남고, 목표 미달 항목이 후속 과제로 나뉜다.

### Phase 6: 집필 문턱 — 갖춰야 쓴다

- **목표**: 내장 에이전트는 계획 없는 회차의 본문을 쓰지 못하고, 앞 회차의 밀린 정산을 먼저 따라잡는다.
- **포함 기능**: 계획 문턱, 정산 기록, 밀린 정산 따라잡기, 외부 클라이언트 경고
- **예상 소요**: 1.5일
- **작업지시서**: [`phase-6-writing-gates.md`](./phase-6-writing-gates.md)
- **Checkpoint 요약**: 계획 없는 빈 회차를 쓰라고 하면 계획부터 쓰고, 직접 고친 앞 회차가 다음 회차 전에 정산된다.

### Phase 7: 비밀과 앎 — 누가 무엇을 아는가

- **목표**: 작가 진실, 독자 앎, 인물 앎을 나눠 알고, 앎이 거꾸로 가면 코드가 충돌로 알리고, 누설은 정산이 보고한다.
- **포함 기능**: 질문의 답, 앎의 대상, 시점별 앎, 앎 충돌, 브리프 섹션, 누설·앎 위반 보고, 패널
- **예상 소요**: 3일
- **작업지시서**: [`phase-7-secrets-and-knowledge.md`](./phase-7-secrets-and-knowledge.md)
- **Checkpoint 요약**: 앎 유형 값 비교 재현율이 0에서 0.8 이상으로 오르고, 지불 회차 앞뒤로 브리프의 비밀이 달라진다.

### Phase 8: 작중 시간 — 그 일로부터 얼마나 지났는가

- **목표**: 기준 사건으로부터의 경과를 원장이 일 수로 알고, 같은 사건의 경과가 이야기 흐름과 맞지 않으면 코드가 충돌로 알린다. 브리프는 회차 시점의 경과를 보여 준다.
- **포함 기능**: 기준 사건과 경과 사실, 경과·나이 충돌, 시간 도약 안내, 브리프 섹션, `시간 모순:` 보고, 패널, (작가 결정) 회상 표시
- **예상 소요**: 3일
- **작업지시서**: [`phase-8-story-time.md`](./phase-8-story-time.md)
- **Checkpoint 요약**: 경과 유형 값 비교 재현율 0.8 이상. #346의 "석 달 → 삼 년" 조건에서 쓰는 에이전트가 모순을 만들지 않고, 심어 둔 모순은 정산이 보고한다.

## 2차 계획: Phase 6~7 (2026-11-07)

Phase 5의 측정에서 두 가지가 남았다. 하나는 쓰기 전에 갖춰야 할 것을 여전히 프롬프트로만 말한다는 점이다. 다른 하나는 앎 유형의 재현율이 0이고 모델 대조의 인물별 지식이 7/12라는 점이다. [Oh Story](https://github.com/zenstory-ai/oh-story-claudecode)를 비교하다가 두 가지 해법을 봤다. 집필 전 문턱, 그리고 작가 진실과 독자 앎의 분리다. 이 계획은 둘을 리네타의 기존 구조로 옮긴다.

- **새 집필 계약을 만들지 않는다.** 계획은 `nodes.plan`, 작가 지시는 씬 의도와 고른 갈래다. 문턱은 "있는가"만 본다.
- **문턱은 내장 에이전트만 거절한다.** `briefgate.go`의 원칙을 따르고, 외부 클라이언트에는 경고를 준다.
- **독자 앎은 기록하지 않고 계산한다.** 독자가 기다리는 비밀은 `question`이고, 밝혀진 회차는 `paid_node_id`다.
- **누설은 코드로 찾지 않는다.** 앎의 방향은 코드가 비교하고, 서술자의 누설은 정산 패스가 읽어서 보고한다.

Oh Story에서 보고 **가져오지 않은 것**:

- 베스트셀러 해체와 순위 훑기: 남의 작품 원문을 다루고 리네타의 방향과 멀다.
- 파생 문서의 손 편집 거부: 리네타의 현재 상태는 이미 조회 결과다. 모델이 쓴 문서가 아니다. 대체된 사실도 지우지 않고 남긴다.
- 세부 개요 표 양식: 위의 "새 집필 계약을 만들지 않는다"와 같은 이유다.

| 기존 작업 | 2차 계획의 처리 |
|---|---|
| `briefgate.go` 브리프 문턱 | 유지한다. 계획 문턱은 그 뒤에 같은 모양으로 둔다. |
| `nodes.plan`, 씬 의도, 고른 갈래 | 그대로 계획으로 읽는다. 쓰는 경로를 바꾸지 않는다. |
| Phase 3 정산 패스, 기본 꺼짐 | 유지한다. 따라잡기는 켜진 경우에만 돈다. |
| `ledger.Conflicts`의 앎 건너뛰기 | `about`이 없는 앎은 계속 건너뛴다. 있는 앎만 비교한다. |
| 표본 대조, 브리프 없이 읽기 | 바꾸지 않는다. 답을 넣지 않는다. |

## 페이즈 간 의존성

```
Phase 1 (브리프 용량)
  ├─→ Phase 2 (작가 경계)
  └─→ Phase 3 (시점 사실과 정산)
        └─→ Phase 4 (아크 결산과 영향 검사)
              └─→ Phase 5 (규모 평가)
                    └─→ Phase 6 (집필 문턱)
                          └─→ Phase 7 (비밀과 앎)
                                └─→ Phase 8 (작중 시간)
```

**Phase 8의 근거**: 2026-11-09 합성 종단검증(#346)에서 에이전트가 "석 달"을 "삼 년"으로 바꿔 썼고, 정산과 검수가 놓쳤다. Phase 7이 앎에 `about`을 붙여 비교를 가능하게 한 방식을 경과에 그대로 쓴다. 그래서 Phase 7 뒤에 둔다.

**Phase 6과 7의 순서**: 둘 다 `settlement.go`와 `prompt.go`를 고친다. Phase 7의 정산 호출 예산은 Phase 6의 측정 기록으로 정한다. 그래서 차례로 한다.

**병렬 가능성**: Phase 2와 Phase 3은 Phase 1 뒤에 나눌 수 있지만 둘 다 `story_ledger`와 `ledger/brief.go`를 고친다. 마이그레이션 번호가 겹치지 않게 순서대로 한다.

## 작품 운영 규칙

코드 밖의 약속이다. 앱이 강제하지 않고 Phase 2~4의 기능으로 돕는다. 숫자는 출발값이며 검증된 값이 아니다.

- 권은 약 100화, 아크는 15~25화로 잡는다.
- 복선은 작품 범위 5~7개, 권 범위 10개 이내로 두고 나머지는 아크 안에서 회수한다.
- 불변 규칙은 게시 전에 고정한다. 설정 변경은 아크 경계에서 한다.
- 게시분은 정본으로 보고 앞으로만 수정한다. 뒤집을 여지가 필요한 내용은 서술자가 단정하지 않고 대사나 소문으로 쓴다.
- 권마다 활성 인물을 8~12명으로 제한한다.
- 20화 이상 비축하고, 비축분 안에서만 뒤로 돌아가 고친다.
- 결말에 걸린 규칙과 독자가 기억할 사실을 먼저 지킨다.

## 페이즈 간 전환 규칙

각 페이즈는 다음을 만족해야 완료로 본다.

1. 작업지시서의 모든 체크박스 완료
2. Checkpoint의 모든 검증 통과
3. 작가가 명시적으로 다음 진행을 승인

Checkpoint가 실패하면 원인을 보고하고, 함께 파악해 수정한 뒤 다시 검증한다.

페이즈마다 `main`에서 새 브랜치를 따서 PR을 연다. 병합은 작가가 승인한 뒤에만 한다.
