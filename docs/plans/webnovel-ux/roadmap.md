# 웹소설가 UI/UX 개선 — 개발 로드맵

_이 문서는 전체 개발 계획의 **총괄본**. Claude Code는 이 로드맵을 먼저 읽고 전체 맥락을 파악한 뒤, 각 페이즈 작업지시서로 이동해서 실제 구현을 진행한다. 페이즈 간 전환 시 반드시 사용자 확인을 받는다._

_작성일: 2026-06-10_
_예상 전체 소요: 약 2~3주 (파트타임 기준)_
_페이즈 수: 3개_

## Overview

Linetta는 아웃라인·엔티티·플롯·AI 컴패니언을 갖춘 장편소설 집필 앱이지만, 한국 웹소설가의
실제 작업 단위인 **"회차(화) + 공백 포함 글자수 + 매일 연재"** 루프가 UI에 없다.

- 글자수 목표가 영어 단어 수 기준(`TARGET_WORDS: novel 90000`)이라 한국 작가의 멘탈 모델
  ("공백 포함 5,000자/회")과 어긋난다.
- 회차(화) 단위 합산 글자수가 어디에도 표시되지 않는다 (씬 단위와 작품 전체만 존재).
- 연재 워크플로(회차 상태, 비축분, 오늘 쓴 글자수, 플랫폼 붙여넣기용 본문 복사)가 없다.
- 웹소설 아웃라인 프리셋이 아웃라인 닥터(청진기 아이콘) 안에 숨어 있어 발견 불가능하다.

이 로드맵은 **기존 데이터(word_count 트리, export 파이프라인, ZenMode target prop)를
웹소설가의 언어로 다시 보여주는 것**을 우선하고, 그다음 구조·에디터 환경, 마지막으로
차별화 기능(통계·플랫폼 프로필·AI 퇴고) 순으로 진행한다.

## 완료 조건 (전체)

- [ ] 웹소설 프리셋 프로젝트에서 화(회차) 단위 글자수와 목표 게이지가 아웃라인·에디터 푸터·ZEN에 표시된다
- [ ] 회차 본문을 플랫폼(문피아/네이버시리즈 등) 에디터에 바로 붙여넣을 수 있는 플레인 텍스트 복사가 동작한다
- [ ] 새 프로젝트 생성 시 "웹소설 연재"를 첫 화면에서 선택할 수 있고, 한국 웹소설 장르 칩이 제공된다
- [ ] 회차 상태(초고/퇴고/탈고/발행)와 비축분 카운트가 보인다
- [ ] 다크 모드와 에디터 폰트/크기/줄간격 설정이 동작한다
- [ ] 일별 집필량 통계(오늘 쓴 글자수 → 대시보드)가 동작한다

## 기술 스택 / 환경

- **프론트엔드**: Tauri 2 + React 18 + Vite + TypeScript, Tiptap 에디터, lucide-react 아이콘
- **엔진**: Go (JSONRPC stdio 사이드카), SQLite (`engine/internal/store`)
- **i18n**: `apps/desktop/src/lib/i18n.tsx` — 모든 신규 문자열은 `MessageKey` union 추가 + **ko/en/ja 3개 메시지 맵 전부** 채울 것
- **테스트**: 프론트 Vitest(`*.test.tsx`, CSS 계약 테스트 `*.css.test.ts`), 엔진 Go(`*_test.go`)
- **검증 명령**: `make test` (전체 게이트) / `make test-go` / `make test-desktop`

주요 기존 컨벤션 (작업 시 참조):

| 영역 | 패턴 위치 |
|---|---|
| RPC 클라이언트 | `apps/desktop/src/lib/rpc.ts` |
| RPC 핸들러 (엔진) | `engine/internal/rpc/handlers/*.go` (예: `nodes.go`, `export.go`) |
| 글자수 계산 | `engine/internal/node/word_count.go` `CountChars` (프론트는 `Tiptap.tsx`의 counter) |
| 아웃라인 프리셋 | `apps/desktop/src/lib/outlineRepair.ts` `OUTLINE_PRESETS` |
| 설정 | `engine/internal/settings/settings.go` + `lib/types.ts` `Settings`/`SettingsPatch` + `routes/Settings.tsx` |
| 커맨드 팔레트 | `routes/Workspace.tsx` — 섹션 8개 고정 (이동·보기·노드·엔티티·프로젝트·AI·내보내기·도움말), 9번째 추가 금지 |

## Out of Scope

- **맞춤법 외부 검사기(부산대/다음) 연동**: 외부 서비스 의존 + 약관 이슈. AI 퇴고 프리셋(Phase 3)으로 대체
- **연재 캘린더 / 발행 예약**: 플랫폼 API가 없어 알림 기능에 그침. 통계 대시보드로 충분
- **플랫폼 자동 업로드**: 각 플랫폼 비공개 API. 복사/내보내기 프로필까지만
- **우측 패널 멀티 스택(동시 표시)**: 레이아웃 전면 개편 필요. 현행 스왑 구조 유지
- **모바일/태블릿 대응**

## 페이즈 구성

각 페이즈는 **수직 슬라이스** — 끝나면 동작하는 무언가가 나오는 단위.

### Phase 1: 연재 핵심 단위 — 회차 글자수·복사·온보딩

- **목표**: 웹소설가가 "이번 화 몇 자 썼는지" 항상 보이고, 다 쓴 회차를 플랫폼에 바로 붙여넣을 수 있다
- **포함 기능**: 회차 합산 글자수 + 게이지, 회차 글자수 목표(프로젝트 필드), 본문 플레인 텍스트 복사, 새 프로젝트 작품 유형 선택 + 웹소설 장르, ZEN 목표 진행바 연결, 오늘 쓴 글자수
- **예상 소요**: 3~4일
- **작업지시서**: [`phase-1-serial-core.md`](./phase-1-serial-core.md)
- **Checkpoint 요약**: 웹소설 프로젝트에서 화 글자수 게이지·회차 복사·일일 글자수가 실제 동작

### Phase 2: 구조·에디터 환경 — 마찰 제거

- **목표**: 회차 50개 이상의 연재 프로젝트를 스트레스 없이 관리하고, 밤에도 쓸 수 있는 에디터 환경
- **포함 기능**: 회차 상태(발행 추가) + 비축분 카운트, 화 직접 집필(권>화 2단계), 아웃라인 인라인 rename, 드래그 앤 드롭 재배치, 다크 모드 + 에디터 폰트/크기/줄간격 설정, 단축키 도움말 보강
- **예상 소요**: 4~5일
- **작업지시서**: [`phase-2-structure-editor.md`](./phase-2-structure-editor.md)
- **Checkpoint 요약**: 발행/비축 상태 추적, DnD 재배치, 다크 모드 전환이 실제 동작

### Phase 3: 차별화 — 통계·플랫폼 프로필·AI 퇴고

- **목표**: "연재를 지속하게 만드는" 동기부여 장치와 마무리 품질 도구
- **포함 기능**: 집필 통계 대시보드(일별 히트맵·평균 속도·완결 예상), 플랫폼별 복사 프로필(문단/말줄임표 규칙), AI 퇴고 원클릭 프리셋
- **예상 소요**: 3~4일
- **작업지시서**: [`phase-3-stats-platform.md`](./phase-3-stats-platform.md)
- **Checkpoint 요약**: 통계 화면, 플랫폼 프로필 복사, 선택 영역 AI 퇴고가 실제 동작

## 페이즈 간 의존성

```
Phase 1 (연재 핵심 단위)
  ├─→ Phase 2 (구조·에디터 환경)   # 회차 개념(화 단위 표시)을 전제로 상태/DnD 작업
  └─→ Phase 3 (통계·플랫폼·퇴고)   # Phase 1의 writing_stats 테이블과 plainText export를 확장
```

**병렬 가능성**: Phase 2와 Phase 3은 Phase 1 완료 후 독립적으로 진행 가능.
단, Phase 3의 통계 대시보드는 Phase 1의 `writing_stats` 데이터가 쌓여 있어야 의미 있는 화면이 나온다.

## 페이즈 간 전환 규칙

각 페이즈는 다음 조건을 만족해야 완료로 간주:

1. 작업지시서의 모든 체크박스 완료
2. Checkpoint 블록의 모든 검증 통과 (`make test` 포함)
3. 사용자가 명시적으로 "Phase N 완료, 다음 진행" 승인

Checkpoint 실패 시: 실패 항목 보고 → 원인 파악 → 수정 → 재검증 → 사용자 승인.
