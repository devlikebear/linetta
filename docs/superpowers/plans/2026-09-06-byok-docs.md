# README·개인정보 정책·사이트·CHANGELOG — BYOK와 내장 에이전트 문구 (#96)

에픽 #90 서브프로젝트 1의 마지막 단계. 설계 문서
`docs/superpowers/specs/2026-09-02-builtin-agent-byok-design.md` 12절.

## 왜 이 이슈가 존재하는가

1.0은 세 곳에 "Linetta는 모델을 호출하지 않는다"고 썼다. #91~#95가 그 문장을
거짓으로 만들었다. 이 이슈가 고치지 않으면 앱이 개인정보 문서에서 사실이 아닌
것을 말하는 상태로 릴리스된다.

**이 브랜치는 #94(PR #110)와 #95(PR #111) 위에 쌓인다.** 순서대로 머지되므로
문구가 코드보다 먼저 나갈 일이 없다. #96의 전제 — "구현이 머지된 뒤에 문구를
바꾼다" — 는 스택 순서로 지켜진다.

### 이미 모순이던 것

**#92가 Codex 토큰 절(2절)을 추가하면서 3절의 포괄 문장은 그대로 뒀다.**
`privacy-policy.md`는 2절에서 "ChatGPT(Codex)로 로그인하면 접근 토큰과 갱신
토큰이 `<앱 데이터>/codex/auth.json`에 저장된다"고 말하고, 3절에서 "API 키를
저장하지도 않는다"고 말한다. #92 시점부터 이미 앞뒤가 안 맞았다. 이 이슈가
그것도 고친다.

### 이슈 본문과 다른 것

- `docs/privacy-policy.md`는 **파일 하나**에 ko/en/ja가 `## 한국어` / `## English`
  / `## 日本語` 절로 들어 있다. 이슈는 "ko/en/ja"라고만 적어 세 파일처럼 읽힌다.
- `docs/migrating-to-1.0.md`의 "What happened to your API keys" 절이 이미
  존재하고, "Linetta no longer reads them"과 "Your provider selection and model
  choices stay in `settings.json`. Nothing reads them; a future release may
  clean them up"이라고 말한다. **1.2가 바로 그 future release다.** 이슈가 요구한
  "한 문단"은 새 절이 아니라 이 두 문장의 정정이다.
- 사이트 문구는 `apps/site/src/lib/content.ts` 한 파일에 모여 있다.

## Global Constraints

- **코드가 실제로 하는 것만 쓴다.** 프로바이더는 정확히 넷
  (`openai-codex`, `anthropic`, `gemini-native`, `openai`), 동의는 **프로바이더별**,
  API 키는 **OS 보안 저장소**에만, Codex 토큰은 `<앱 데이터>/codex/auth.json`에
  0600으로. 확인하지 않은 것은 쓰지 않는다.
- **세 언어가 같은 사실을 말한다.** 1.0의 "언어별 파일 불일치"를 반복하지 않는다.
  한 언어에만 있는 문장이 있으면 그건 결함이다.
- **스크린샷은 찍지 않는다.** 에이전트 패널이 실제로 손에 잡히는 빌드가 나온 뒤의
  일이다. 사이트에 이미지 자리를 비워두더라도 없는 화면을 그리지 않는다.
- **버전 파일 7개는 건드리지 않는다.** 그건 릴리스 PR의 일이다. CHANGELOG의
  `1.2.0` 항목만 쓴다.
- **`docs/`, `apps/site/`, `README.md`, `CHANGELOG.md`만 건드린다.** 엔진도
  `apps/desktop`도 아니다.

## 무엇이 참인가 — 문구가 서야 할 사실

새 문장의 뼈대는 이것이고, 세 언어가 이것을 말해야 한다:

> Linetta는 **작가가 연결한 프로바이더에만** 원고를 보내며, 그마저도 작가가
> **프로바이더별로 동의한 뒤에만** 보낸다. 연결하지 않으면 아무 데도 보내지 않는다.

그리고 무엇이 가는지도 말해야 한다. 설계 문서 5.4절이 요구하는 목록:
현재 씬 본문, 요약, 등장인물·플롯·팩트 카드 등 에이전트가 툴로 읽은 내용.
`#95`의 동의 문구가 이미 세 언어로 이 목록을 말하고 있으니, 문서가 그보다
좁게 말하면 문서가 틀린 것이다.

## Task 1: README

### 파일

`README.md`

### 1-1. 고칠 문장 셋

**8행 (부제)** — 현재:
> When you want to write alongside AI, connect the agent you already use over MCP — the manuscript never leaves your machine on its own.

MCP만 말하고 내장 에이전트를 모른다. 그리고 뒷절은 이제 거짓이다. 두 경로를
다 말하되, 어느 쪽도 저절로 일어나지 않는다는 사실을 남긴다.

**27행 (기능 목록)** — 현재:
> **Stay in control of AI.** Linetta itself never calls a model. Connect your own agent over MCP when you want one, see everything it changed, and undo any of it.

"never calls a model"만 빼고 나머지는 살아 있다 — 무엇이 바뀌었는지 보고 되돌리는
건 여전히 참이고, 이제 내장 에이전트에도 해당한다. 활동 로그가 내장 에이전트와
외부 클라이언트를 구분해 보여준다는 것(#94)도 여기 들어갈 만하다.

**129행 (FAQ "Do I have to use AI?")** — 현재:
> No. Linetta is a complete writing app on its own and never contacts a model. AI …

"쓰지 않아도 된다"는 답은 그대로 참이다. 고칠 것은 이유다: 모델을 못 부르는
앱이라서가 아니라, **작가가 프로바이더를 연결하고 동의하기 전에는 부르지
않기 때문**이다.

### 1-2. 새 절 "Writing with the built-in agent (BYOK)"

78행의 "Writing with your own agent (MCP)" 절 **앞에** 놓는다. 작가가 먼저 만나는
것이 내장 에이전트이고, MCP는 외부 도구를 쓰는 사람의 선택지다.

절이 말해야 하는 것, 그리고 그것뿐:

- 프로바이더 넷. ChatGPT 계정으로 로그인(Codex), Anthropic·Google Gemini·
  OpenAI 호환 엔드포인트는 API 키.
- 키는 OS 보안 저장소에 들어간다. `settings.json`에 들어가지 않는다.
- 동의는 프로바이더별이고, 동의 전에는 연결 테스트조차 안 된다.
- `Cmd/Ctrl+J`로 패널을 연다.
- 에이전트가 쓴 것은 활동 로그에 남고, 구조 변경은 되돌릴 수 있다.
  **씬 본문 되돌리기는 아직 없다** (#112) — 쓰지 않거나, 없다고 쓴다.
  있다고 쓰면 안 된다.
- 연결하지 않으면 아무 데도 보내지 않는다.

### 1-3. 하지 말 것

- 모델 이름을 쓰지 않는다. 프로바이더가 바꾸고 README가 낡는다.
- 가격을 쓰지 않는다.
- 스크린샷을 넣지 않는다.

### 파일

### 2-1. 세 언어의 도입부

ko 9행 / en 62행 / ja 116행의 "앱 자체는 어떤 언어 모델과도 통신하지 않습니다"

**프로바이더별 동의 뒤에만** 보낸다.

### 2-2. 3절 — 가장 중요한 수정

ko 35행 / en 88행 / ja 대응 행의 포괄 문장:
> **앱은 어떤 AI 공급자에게도 데이터를 보내지 않습니다.** API 키를 저장하지도,
> 모델을 호출하지도 않습니다.

**두 문장 다 거짓이고, 두 번째는 #92 시점부터 거짓이었다** — 같은 문서 2절이
Codex 토큰을 `auth.json`에 저장한다고 이미 말하고 있다.

3절을 두 갈래로 다시 쓴다:

**3-가. 내장 에이전트 (BYOK)** — 새로 쓴다.
- 어디로 가나: 작가가 고른 프로바이더. 넷의 이름을 적는다. OpenAI 호환 항목은
  작가가 넣은 base URL로 간다는 것도 — OpenRouter일 수도, 이 기계를 떠나지
  않는 로컬 엔드포인트일 수도 있다.
- 무엇이 가나: 현재 씬 본문, 요약, 등장인물·플롯·팩트 카드 등 에이전트가
  툴로 읽은 내용. **패널의 동의 문구가 이미 세 언어로 이 목록을 말한다**
  (#95). 문서가 그보다 좁게 말하면 문서가 틀린 것이다.
- 언제 가나: 프로바이더별로 동의한 뒤에만. 동의 전에는 연결 테스트도 거절된다.
- 자격증명이 어디 있나: API 키는 OS 보안 저장소, Codex 토큰은
  `<앱 데이터>/codex/auth.json`에 0600. **2절이 이미 이걸 말하니 반복하지 말고
  가리킨다.**
- 프로바이더가 그 데이터로 무엇을 하는지는 그 회사의 정책 소관이라고 밝힌다.
  Linetta가 대신 약속할 수 없다.

**3-나. 외부 에이전트 (MCP)** — 기존 내용. 거의 그대로 살린다.

### 2-3. 4절·5절

- 4절(데이터 판매·공유): MCP만 언급한다. 내장 에이전트 경로를 추가한다.
- 5절(아동): "MCP로 연결하는 클라이언트의 연령 요건"을 확인하라고 되어 있다.
  프로바이더의 연령 요건도 같은 이유로 해당한다.

### 2-4. 세 언어 대조

**작업의 마지막 단계로, 세 절을 나란히 놓고 문장 단위로 대조한다.** 한 언어에만
있는 문장, 한 언어에서만 더 강한 주장, 한 언어에서만 빠진 목록 항목 — 전부 결함이다.
1.0에서 정확히 이 문제가 있었다.

## Task 3: 1.0 마이그레이션 문서

### 파일

`docs/migrating-to-1.0.md`

### 3-1. 고칠 것

"What happened to your API keys" 절(22행~)이 이미 있고, 두 문장이 1.2에서
거짓이 된다:

> They are untouched. **Linetta no longer reads them**, but it does not delete
> credentials you own.

> Your provider selection and model choices stay in `settings.json`. **Nothing
> reads them; a future release may clean them up.**

**1.2가 그 future release다.** 1.0 때 남겨둔 키와 프로바이더 선택을 다시 쓴다.

이슈는 "한 문단 추가"라고 했지만, 실제로 필요한 건 **이 두 문장의 정정**이다.
새 문단을 아래에 붙이고 위 문장을 그대로 두면 문서가 자기와 싸운다.

### 3-2. 무엇을 말해야 하나

- 1.0에서 지우지 않은 키가 1.2에서 다시 쓰인다.
- 다시 쓰이려면 여전히 **프로바이더별 동의**가 필요하다. 남아 있다는 이유만으로
  조용히 다시 쓰이지 않는다.
- 지우고 싶었던 사람은 아래 표대로 지우면 되고, 그 안내는 그대로 유효하다.
- `settings.json`의 프로바이더 선택도 다시 의미를 갖는다.

문서의 제목이 "migrating to 1.0"이므로, 1.2를 말하는 것이 어색해 보일 수 있다.
그래도 여기가 맞다 — 1.0에서 키를 남겨둔 사람이 읽는 문서가 이것이고, 그 사람이
알아야 할 변화다. 절 제목에 1.2를 명시한다.
