# 장편 지원 범위

리네타가 긴 연재에서 무엇을 어디까지 확인했는지 적는다. 측정한 것과 하지 않은 것을 나눈다. 이 문서는 일관성을 보장하지 않는다.

_측정일: 2026-11-02, 앎과 브리프 크기는 2026-11-07(Phase 7), 모델 대조는 2026-11-09(Haiku, Sonnet). 재현 방법은 [평가 형식](./plans/longform-continuity/eval-format.md)을 본다._

## 요약

| 규모 | 상태 |
|---|---|
| 16화 | 실제 작품으로 사용하고 측정했다 |
| 25화까지 | 실제 작품 데이터로 브리프와 목록을 측정했다 |
| 1,000화 | 합성 작품으로 용량과 속도만 측정했다. 일관성은 측정하지 않았다 |
| 100화 이상의 실제 작품 | **미검증** |

## 용량과 속도

합성 작품 1,000화, 세계관 요소 3,500개, 원장 3,600건이다. 실제 작품의 증가율로 만들었다. Phase 7부터는 답이 있는 질문 200개와 그에 대한 앎 200건을 더해 4,000건으로 잰다.

| 지표 | 결과 | 기준 |
|---|---|---|
| 내장 에이전트 브리프의 도구 결과 최대 크기 | 21,964자 (비밀과 앎 섹션 포함, 이전 21,242자) | 24,000자 이내 |
| 브리프 조립 p95 | 215~445ms | 1초 이내 |
| 브리프의 복선 수 | 19화부터 999화까지 34~35개 | 회차 수에 비례하지 않음 |
| 원장 목록 | 78페이지로 4,000건 전부 | 빠짐 없음 |
| 세계관 목록 | 65페이지로 3,500개 전부 | 빠짐 없음 |
| 개요 | 11페이지로 1,060행 전부 | 빠짐 없음 |

실제 작품 25개 회차의 브리프 도구 결과는 최대 22,574자다. 9개 회차는 자료집이 빠지고 그 사실을 `omitted_sections`로 알린다.

## 일관성

합성 사례 64건이다. 여덟 유형에 모순과 정상이 절반씩 있다. 합성 문장은 짧고 깔끔해서 실제보다 성적이 좋게 나온다.

| 평가 | 정밀도 | 재현율 | 초기 목표 |
|---|---|---|---|
| 값 비교 (코드, 사실이 바르게 기록된 경우) | 1.00 | 1.00 | 달성 |
| 모델의 두 장면 대조 (Haiku `claude-haiku-5-5`, 3회 192건) | 1.00 | **0.77** | 정밀도 달성, 재현율 미달 |
| 모델의 두 장면 대조 (Sonnet `claude-sonnet-5-5`, 3회 192건) | 0.99 | 0.84 | 달성 |
| (이전) 경량 모델, 2026-11-02, 3회 192건 | 0.93 | 0.72 | 정밀도 달성, 재현율 미달 |

목표는 #141의 초기값인 정밀도 90%, 재현율 80%다. Sonnet은 집필에 쓰는 모델과 같은 급이고, Haiku는 이전 수치와 같은 경량 모델 조건이다. 두 모델 모두 Claude Code CLI로 도구 없이 물었고 684회 호출에서 실패와 타임아웃은 0건이다.

유형별로 모순 사례를 몇 번 찾았는지 적는다. 유형마다 모순 4건을 3회 물어 12번이다. 사례가 4건뿐이라 한 사례를 세 번 모두 놓치면 3/12가 바뀐다. 모델 사이의 유형별 차이는 그 정도 크기로 읽는다. 정상 사례에 모순이라고 답한 경우는 Haiku 0/96, Sonnet 1/96(죽음과 부활)이다.

| 유형 | Haiku | Sonnet | 이전 경량 모델 |
|---|---|---|---|
| 날짜 | 12/12 | 9/12 | 11~12/12 |
| 죽음과 부활 | 6/12 | 12/12 | 5/12 |
| 소지품 | 9/12 | 12/12 | 8/12 |
| 인물별 지식 | 6/12 | 12/12 | 7/12 |
| 관계 | 12/12 | 12/12 | 11~12/12 |
| 별명 | 10/12 | 8/12 | 11~12/12 |
| 회상 | 7/12 | **4/12** | **2/12** |
| 거짓말 | 12/12 | 12/12 | 11~12/12 |

- **값 비교의 한계:** `앎`은 대상 질문(`about`)과 방향(`value_num` 1 또는 0)이 함께 기록된 경우에만 비교한다. 그렇게 기록된 합성 8건(모순 4, 정상 4)에서 재현율 1.00, 정밀도 1.00이다(Phase 7, 이전 0). 사실이 바르게 기록되었다는 가정의 값이다. `about`이 빈 옛 앎 행은 지금도 비교하지 않고, 정산이 앎을 바르게 기록하는지는 재지 않았다. 주어와 속성이 다르게 기록되면 찾지 못한다.
- **모델 대조의 약점:** 두 모델 모두 회상이 가장 약하다(Haiku 7/12, Sonnet 4/12). Haiku는 죽음과 부활, 인물별 지식이 절반이다. Sonnet은 이 둘과 소지품을 모두 찾지만 날짜(9/12)와 별명(8/12)에서 Haiku보다 덜 찾는다. Sonnet이 놓친 날짜와 별명 사례는 같은 사례에 몰려 있다(날짜 2건, 별명 2건). 별명이 다른 사람일 수 있다고 읽는 것처럼 다른 해석을 허용한 것으로 보이지만 답의 이유는 받지 않았으므로 확인하지 않았다. 이전 경량 모델보다 Haiku가 나은 차이(0.72에서 0.77)는 실행 조건이 달라졌으므로 모델이 나아졌다고 말할 수 없다. 이번에는 CLI가 실패하거나 첫 줄이 YES/NO가 아닌 답을 오류로 세고 `--safe-mode`로 작가의 설정을 뺐다. 이전에는 그런 답을 NO로 셌다. 이 대조는 브리프 없이 두 장면만 읽으므로 브리프의 `## 비밀과 앎`이 이 수치에 닿지 않는다. 표본 대조에도 답을 넣지 않는다. 브리프를 받은 집필 에이전트가 누설과 앎 위반을 얼마나 피하는지는 재는 방법이 아직 없다.
- **둘은 서로 보완한다.** 코드는 회상과 죽음을 잡지만 기록에 의존하고, 모델은 기록 없이 읽지만 놓침이 있다.
- **긴 구간 읽기:** 두 장면을 무관한 장면 사이에 숨긴 22건(모순 11건)에서 Haiku는 재현율 0.82, 정밀도 0.82, Sonnet은 둘 다 1.00이다. 같은 사례의 두 장면 대조 첫 회는 Haiku 0.73, Sonnet 0.82다. 이전 경량 모델은 숨긴 경우 0.73, 두 장면 대조 0.64였다. 숨겼는데 더 잘 찾는 것은 채운 문장이 같은 문단의 반복이라 두 장면이 오히려 눈에 띄기 때문일 수 있다. 표본이 작고 1회만 쟀으므로 차이가 있다고 말할 수 없다.

## 영향 찾기와 표본 대조

- **영향 후보:** 합성 모순 32건 중 28건에서 상대 회차가 후보에 들었다.
- **표본 일정:** 실제 작품의 기록된 모순 쌍 9개 중 8개를 대조 54회로 덮었다. 먼 쌍은 3개 중 2개다. 덮었다고 모델이 찾는다는 뜻은 아니다.
- **남은 모순 추정:** 독립 실행 두 번의 겹침으로 추정하면 Haiku 28.5건, Sonnet 29.0건이고 실제는 32건이다(이전 경량 모델 25~29건). 찾기 어려운 사례가 겹치지 않아 **적게** 나온다. 하한으로만 쓴다.

## 측정하지 않은 것

- **실제 Claude Code 경로의 패스.** 정산, 독립 검수, 영향 검사, 표본 대조를 가짜 CLI로만 시험했다. 앱에서 실제로 돌린 적이 없다. 작가의 AI 데이터 공유 동의가 필요하다.
- **실제 원고에서의 모델 탐지력.** 위 모델 수치는 합성 사례의 값이다. 집필 모델 급(Sonnet)으로도 쟀지만 짧고 깔끔한 합성 문장에서 두 장면만 본 값이다. 실제 원고의 긴 회차에서 같은 성적이 나온다는 뜻이 아니다.
- **정산이 사실을 바르게 기록하는가.** 값 비교는 바르게 기록됐다고 가정한다.
- **장기 사용.** 몇 달에 걸친 연재, 수백 화의 실제 원장과 아크 결산은 해 보지 않았다.

## 권장 운영

- 권은 약 100화, 아크는 15~25화로 잡고 아크 경계에서 설정을 바꾼다.
- 불변 규칙은 게시 전에 원장에서 고정한다.
- 게시분은 정본으로 보고 앞으로만 수정한다. 뒤집을 여지가 필요하면 대사나 소문으로 쓴다.
- 복선은 작품 범위 5~7개, 권 범위 10개 이내로 두고 나머지는 아크 안에서 회수한다.
- 권마다 활성 인물을 8~12명으로 제한한다.
- 20화 이상 비축하고 비축분 안에서만 뒤로 돌아가 고친다.
- 큰 설정 변경은 작품을 복제해서 시험한다.

이 숫자는 출발값이며 검증된 값이 아니다. 작가의 최종 검수를 대신하지 않는다.
